# 📨 Telegram-бот анонимных сообщений

Бот выдаёт каждому пользователю персональную ссылку. Любой, кто перейдёт по ней, может отправить владельцу анонимное сообщение. Владелец видит сообщение от имени бота, может ответить на него, заблокировать отправителя, а с премиумом, при желании, узнать, кто это был.

Написан на [aiogram](https://docs.aiogram.dev/) 3.x (асинхронный, на роутерах и FSM), данные хранит в SQLite.

> Форк [kkaifddkk/telegram-anonymous-feedback-bot](https://github.com/kkaifddkk/telegram-anonymous-feedback-bot), полностью переписанный на aiogram 3.

---

## ✨ Возможности

- 🔗 Персональная ссылка для каждого пользователя и кастомные ссылки (свой текст вместо случайного кода)
- 💬 Анонимные сообщения: текст, фото, видео, голосовые, аудио, GIF, стикеры, документы
- 💌 Ответы отправителю прямо через бота, тоже любых из этих типов
- ⛔ Личные блокировки нежелательных отправителей и глобальный бан от админа
- ⭐ Премиум в отдельной базе `premium_users.db`: кнопка «Узнать отправителя»
- 🎁 Промокоды на временный премиум (`/promo КОД`)
- 🛠 Админ-панель: пользователи, статистика, рассылка, под-админы, премиум, баны, промокоды
- 🧪 Автотесты (pytest), CI в GitHub Actions, Docker с HEALTHCHECK
- 🔌 Опционально: Redis для FSM-состояний и Sentry для ошибок

## 👥 Как это работает для пользователя

1. Напишите боту `/start`.
2. Бот создаст для вас уникальную ссылку вида `https://t.me/<bot_username>?start=<unique_code>`.
3. Разместите её в описании профиля Telegram, в Instagram, TikTok и других соцсетях.
4. Любой, кто перейдёт по ссылке, сможет отправить вам анонимно:
   - 💬 текст
   - 📷 фото или 🎥 видео с подписью
   - 🎙 голосовое сообщение
   - 🎵 аудио
   - 🎞 GIF-анимацию
   - 😀 стикер
   - 📄 документ (исполняемые и установочные файлы блокируются по расширению: `.exe`, `.msi`, `.bat`, `.js`, `.apk`, `.sh`, `.dll` и другие)
5. Лимиты длины: примерно 3900 символов для текста и 820 для подписи к медиа. Лимиты Telegram (4096 и 1024) уменьшены на запас под служебную обёртку сообщения.

Вы получаете сообщение от бота, а не от отправителя.

> **Про границы анонимности.** Анонимность действует «от получателя». Бот хранит `sender_id`, имя и username отправителя в `bot_database.db` (это нужно для премиум-функции «Узнать отправителя»), поэтому владелец бота и админы при желании могут их увидеть. В логах и в Sentry ни личности, ни текст сообщений не пишутся: логируются только тип и длина. Sentry инициализируется без локальных переменных.

## 🧩 Кастомные ссылки

- Вместо случайного кода можно задать свой, например `my_link` или `best_page123`.
- Допустимы латинские буквы, цифры, `_` и `-`, длина от 3 до 20 символов.
- Ввод кириллицей (например «дверь») автоматически транслитерируется в латиницу («dver»), бот сообщит об этом. Так же работает создание промокодов.
- К оригинальной ссылке всегда можно вернуться.

## 💌 Ответы на сообщения

Под каждым входящим сообщением есть кнопки:

- **«Ответить»**: ответ уходит в личку отправителю от имени бота, диалог остаётся анонимным для отправителя;
- **«Заблокировать»**: отправитель больше не сможет писать вам по вашей ссылке.

Ответить можно текстом, фото, видео, голосовым, аудио, GIF, стикером или документом.

## ⛔ Блокировки

### Личный бан

- Кнопка **«Заблокировать»** под сообщением.
- `/blocklist` показывает список заблокированных вами. Имена и username в нём не показываются, пока не куплен премиум. У каждой записи есть кнопка **«🔓 Разблокировать»**.
- `/unblock` — подсказка: разблокировка делается кнопками в `/blocklist`.

### Глобальный бан

- Главный админ и назначенные им под-админы могут полностью заблокировать пользователя. Админов забанить нельзя: сначала нужно снять с них права.
- Забаненного бот полностью игнорирует: `/start`, отправку сообщений, `/promo`, `/blocklist`, `/unblock`.
- Управление админскими командами:
  - `/banlist` — глобальный бан-лист (постранично, с кнопками снятия бана);
  - `/unban ID` — снять глобальный бан по Telegram ID (числом, не по username).

## ⭐ Премиум

Премиум хранится в отдельной базе `premium_users.db`, независимой от `bot_database.db`.

**Что даёт:** кнопку **«👁 Узнать отправителя»** под сообщением. Показываются имя, username (если есть) и Telegram ID.

**Как получить:**

- админ выдаёт его через панель (на +1 / +3 / +5 / +7 дней или на любое число дней), продлевает или снимает;
- пользователь активирует промокод.

Логика премиума находится в `bot/db/premium.py`.

---

## 🎁 Промокоды

- Активация: `/promo КОД`. Регистр не важен, код приводится к верхнему регистру.
- Между попытками действует кулдаун 2 секунды, отдельный от антифлуда на сообщения. Он мешает подбирать код перебором.
- Один пользователь не может погасить один и тот же код дважды.
- У кода можно задать лимит активаций (`max_uses`) или оставить его неограниченным.
- Создание:
  - в админ-панели: **«🎁 Промокоды» → «➕ Создать промокод»**, формат `КОД ДНИ [ЛИМИТ]`;
  - командой `/createpromo КОД ДНИ [ЛИМИТ]`, например `/createpromo SUMMER25 7 100`.
- Просмотр использования и удаление кода (вместе с историей активаций) есть в админ-панели.

## 🛠 Админ-панель

Доступна главному администратору (`MAIN_ADMIN_ID` из `.env`) и назначенным им под-админам. Откройте `/start` или `/admin`, кнопка «⚙️ Админ панель» появится в меню.

- 👥 **Пользователи**: постранично по 10, с ID, именем, username, ссылками и премиум-статусом.
- 📊 **Статистика**: сводка одним экраном (пользователи, сообщения и ответы, активный премиум, личные блокировки, глобальные баны, промокоды).
- 📢 **Рассылка** (мастер из трёх шагов):
  1. аудитория: все или только с активным премиумом;
  2. звук уведомления: со звуком или без;
  3. содержимое: текст или медиа с подписью.

  Перед отправкой показывается предпросмотр с числом получателей и просьба подтвердить. Глобально забаненные исключаются автоматически. Скорость ограничена с запасом от лимитов Telegram. При `TelegramRetryAfter` бот ждёт и повторяет отправку один раз. Тех, кто заблокировал бота, он пропускает и считает отдельно, в конце присылает итог.
- 👤 **Под-админы** (только главный админ): назначить по Telegram ID, снять. Под-админы получают доступ ко всей панели, кроме управления админами.
- ⭐ **Премиум**: выдать, продлить, снять; таблица активных и истёкших записей (постранично).
- 🚫 **Глобальный бан**: забанить, разбанить, отдельный экран бан-листа.
- 🎁 **Промокоды**: создать, посмотреть использование, удалить.
- 👁 **Кто заблокировал пользователя**: список тех, кто внёс его в личный бан, с акцентом на премиум-пользователях и разбаном по кнопке.

## ⚙️ Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | токен от [@BotFather](https://t.me/BotFather) |
| `MAIN_ADMIN_ID` | да | ваш Telegram ID (число): этот аккаунт получает доступ к админ-панели |
| `DATA_DIR` | нет | каталог для файлов БД. По умолчанию текущая папка, в Docker `/app/data` |
| `MESSAGE_COOLDOWN_SECONDS` | нет | минимальный интервал между сообщениями/ответами одного пользователя, по умолчанию `3` |
| `REDIS_URL` | нет | адрес Redis для FSM-состояний |
| `SENTRY_DSN` | нет | DSN проекта в Sentry |

Без `REDIS_URL` состояния FSM (ожидание кастомной ссылки, ввод дней премиума, создание промокода) хранятся в памяти процесса и теряются при перезапуске. С Redis они переживают рестарт. Без `SENTRY_DSN` ничего никуда не отправляется.

> ⚠️ **Никогда не коммитьте `.env` и файлы `*.db`.** В них токен бота и данные пользователей. Для этого в репозитории есть `.gitignore`.

## 🚀 Запуск

Нужен Python 3.12 (на нём работают Docker-образ и CI).

### Через Docker (рекомендуется для VPS)

```bash
cp .env.example .env        # заполните BOT_TOKEN и MAIN_ADMIN_ID
docker compose up -d --build
docker compose logs -f      # логи
docker compose down         # остановить
```

- БД лежат в именованном volume `bot_data`, поэтому пересборка образа (`--build`) их не затрагивает. Посмотреть файлы: `docker compose exec bot ls /app/data`.
- Контейнер работает от непривилегированного пользователя и не открывает входящих портов: бот сам подключается к api.telegram.org (long polling).
- У бота нет HTTP-эндпоинта, поэтому здоровье контейнера определяется по heartbeat-файлу. `main.py` обновляет его каждые 30 секунд, а `HEALTHCHECK` в `Dockerfile` считает контейнер живым, пока файл не старше 90 секунд (`healthcheck.py`).
- Redis подключается по желанию:
  ```bash
  docker compose --profile redis up -d
  ```
  и в `.env`: `REDIS_URL=redis://redis:6379/0` (`redis` — имя сервиса из `docker-compose.yml`).

### Без Docker

```bash
git clone https://github.com/exstinctor/telegram-anonymous-feedback-bot.git
cd telegram-anonymous-feedback-bot
pip install -r requirements.txt
cp .env.example .env        # на Windows: copy .env.example .env
python main.py
```

При первом запуске создаются `bot_database.db` и `premium_users.db`.

## 🧪 Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

`pytest.ini` включает `asyncio_mode = auto` (декоратор на каждый async-тест не нужен) и `pythonpath = .` (без него голая команда `pytest` на Windows может падать с `ModuleNotFoundError: No module named 'bot'`). Тесты работают на собственной временной SQLite-базе (`tests/conftest.py`) и боевые `bot_database.db` и `premium_users.db` не трогают.

На каждый push и pull request в `main` GitHub Actions (`.github/workflows/ci.yml`, Python 3.12) проверяет синтаксис и запускает тесты.

## 🗄 Структура проекта

```
main.py                 точка входа: БД, Bot/Dispatcher, роутеры, heartbeat, polling
healthcheck.py          проверка свежести heartbeat для Docker
bot/
  core/                 config.py (окружение, логи), states.py (FSM), runtime.py, storage.py (Memory/Redis)
  db/                   connection.py, schema.py (таблицы, миграции, индексы),
                        repository.py (SQL-запросы), premium.py (premium_users.db)
  services/             antiflood, security (опасные файлы), attachments (типы и лимиты),
                        filters, dialog (режимы «пишу» и «отвечаю»), permissions,
                        telegram_errors, telegram_ui, utils
  handlers/             start, messages, callbacks, admin, moderation, promo, broadcast
  errors.py             глобальный обработчик ошибок
tests/                  набор pytest
.github/workflows/      CI
Dockerfile, docker-compose.yml, .env.example, requirements*.txt, pytest.ini
```

Таблицы `bot_database.db`: `user_links`, `messages`, `replies`, `blocked_users`, `global_ban_users`, `promo_codes`, `promo_redemptions`, `admins`. В `premium_users.db` одна таблица `premium_users`. Состояние диалогов хранится в `FSMContext`, а не в глобальных переменных.

## 📌 Идеи для доработки

- Веб-панель для администрирования поверх текущей логики.
- Локализация (RU/EN) бота и админ-панели.
- Поиск пользователя в админке по ID или username вместо постраничного просмотра.
- Переход на `aiosqlite`, если БД станет узким местом. Сейчас функции `repository.py` синхронные и без `await` внутри, поэтому гонок между апдейтами нет: цикл событий не прерывает операцию посередине. `asyncio.to_thread` сознательно не добавлен, при текущей нагрузке он дал бы только накладные расходы.
