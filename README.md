 📨 Telegram Анонимный Бот с Премиум‑функциями

Давно хотели узнать, кто вам пишет плохие анонимные сообщения? Этот бот для вас!  
Бот позволяет получать анонимные сообщения по персональной ссылке, отвечать на них, блокировать отправителей и, при наличии премиума, даже узнавать, кто скрывается за сообщением.  

---

 ✨ Основные возможности

- 🔗 Персональная ссылка для каждого пользователя  
- 🧩 Кастомные ссылки (свой текст вместо случайного кода)  
- 💬 Анонимные сообщения: текст, фото, видео, голосовые, аудио, GIF, стикеры, документы  
- 💌 Ответы на сообщения прямо через бота  
- ⛔ Личные блокировки нежелательных отправителей  
- 🚫 Глобальный бан пользователей админом  
- ⭐ Премиум‑система в отдельной базе `premium_users.db`  
- 🎁 Промокоды на временный премиум (`/promo КОД`)  
- 🛠 Удобная админ‑панель для управления ботом, пользователями и промокодами  
- ℹ️ `/help` — список команд (для админа — с дополнительными)  
- ⚙️ Написан на [aiogram](https://docs.aiogram.dev/) 3.x (асинхронный, на роутерах и FSM)  
- 🧪 Покрыт автотестами (pytest) и умеет сообщать Docker о своём здоровье (HEALTHCHECK)  

---

 👥 Как это работает для пользователя

1. Напишите боту `/start`.  
2. Бот создаст для вас уникальную ссылку вида:  
   `https://t.me/<bot_username>?start=<unique_code>`  
3. Разместите эту ссылку:
   - в описании профиля Telegram  
   - в Instagram / TikTok / других соцсетях  
4. Любой, кто перейдёт по ссылке, сможет отправить вам анонимное сообщение:
   - 💬 текст  
   - 📷 фото + подпись  
   - 🎥 видео + подпись  
   - 🎙 голосовое сообщение  
   - 🎵 аудио  
   - 🎞 GIF-анимация  
   - 😀 стикер  
   - 📄 документ (кроме исполняемых/установочных файлов — они блокируются по расширению)  
   - максимум ~3900 символов для текста, ~820 для подписи к медиа (запас от лимитов Telegram — 4096/1024 — на служебную обёртку сообщения)  

Вы получите сообщение от бота, а не от отправителя — его личность останется скрытой (если он не попал под премиум‑функции).

 🧩 Кастомные ссылки

- Можно заменить случайный код на красивый кастомный:  
  пример: `my_link`, `best_page123`  
- Допускаются:
  - латинские буквы  
  - цифры  
  - символы `_` и `-`  
  - длина от 3 до 20 символов  
- Если ввести код кириллицей (например, «дверь»), он автоматически транслитерируется в латиницу («dver») — бот сообщит об этом преобразовании. Так же работает и для промокодов ниже.  
- При желании всегда можно вернуться к оригинальной ссылке.

 💌 Ответы на сообщения

Под каждым входящим сообщением:

- кнопка **«Ответить»** — позволяет написать ответ отправителю  
- ответ отправляется в личку отправителя от имени бота  
- поддерживаются ответы:
  - текстом  
  - фото + текст  
  - видео + текст  
  - голосовым, аудио, GIF, стикером и документом  

Таким образом, диалог остаётся анонимным для отправителя, но при этом вы можете вести общение.

 ⛔ Блокировки

Каждый пользователь может защититься от спама и токсичных сообщений.

 Личный бан

- Кнопка **«Заблокировать»** под сообщением.  
- Заблокированный пользователь больше не сможет отправлять вам сообщения через вашу ссылку.  
- Управление блокировками:
  - `/blocklist` — показывает список всех заблокированных вами  
  - `/unblock @username` — разблокировка по username  

 Глобальный бан

- Главный админ (и назначенные им под‑админы) может полностью заблокировать пользователя в боте.  
- При глобальном бане бот полностью игнорирует этого пользователя — не только `/start` и отправку сообщений, но и `/promo`, `/blocklist`, `/unblock`.  
- Управление — админскими командами (не путать с пользовательскими `/blocklist`/`/unblock` выше — раньше обе пары назывались одинаково и путали и админов, и пользователей):
  - `/banlist` — глобальный бан-лист (постранично, с кнопками снятия бана)  
  - `/unban ID` — снять глобальный бан по Telegram ID (число, не username)

 ⭐ Премиум‑система

Премиум хранится в отдельной базе `premium_users.db`, полностью независимо от основной БД.

 Что даёт премиум

- 👁 Кнопка **«Узнать отправителя»** под сообщением  
- Отображается:
  - имя  
  - username (если есть)  
  - Telegram ID отправителя  

 Управление премиумом

Только через админ‑панель:

- выдача премиума на N дней  
- продление срока  
- полное снятие премиума  

Все премиум‑данные:

- хранятся в файле `premium_users.db`  
- управляются через модуль `bot/db/premium.py`  
- не зависят от `bot_database.db`

 🎁 Промокоды

Способ выдать премиум без ручного вмешательства админа.

- Пользователь активирует код командой: `/promo КОД` (регистр не важен — код нормализуется в верхний регистр)  
- Между попытками — небольшой кулдаун (2 сек), отдельный от антифлуда на отправку сообщений: раньше `/promo` можно было долбить скриптом без всякой задержки, подбирая код перебором  
- Кириллический ввод при создании автоматически транслитерируется в латиницу (см. «Кастомные ссылки» выше)  
- Один и тот же код нельзя погасить дважды одним и тем же пользователем  
- У кода можно задать лимит активаций (`max_uses`) или оставить неограниченным  
- Создание — двумя способами:
  - из админ‑панели: кнопка **«🎁 Промокоды» → «➕ Создать промокод»**, формат `КОД ДНИ [ЛИМИТ]`  
  - напрямую командой: `/createpromo КОД ДНИ [ЛИМИТ]`, например `/createpromo SUMMER25 7 100`  
- Просмотр использования и удаление — тоже из админ‑панели

 🧩 Redis и Sentry (опционально)

Обе зависимости уже в `requirements.txt`, но бот работает и без них — включаются только переменной окружения:

- **Redis** (`REDIS_URL` в `.env`) — состояния FSM (ожидание кастомной ссылки, ввод дней премиума, создание промокода) хранятся в Redis вместо памяти процесса и **переживают перезапуск бота**. Без переменной — как и раньше, `MemoryStorage`, состояния теряются при рестарте. В Docker Compose поднимается отдельным сервисом:

  docker compose --profile redis up -d

  а в `.env` укажите `REDIS_URL=redis://redis:6379/0` (`redis` — имя сервиса из `docker-compose.yml`).

- **Sentry** (`SENTRY_DSN` в `.env`) — необработанные исключения дублируются в Sentry в дополнение к обычным логам. Без переменной — ничего никуда не отправляется, поведение не меняется.

Оба флага реализованы через `bot/core/storage.py` и `main.py:_init_sentry()` — простая проверка "задана ли переменная", без дополнительной логики выбора между реализациями.

 🛠 Админ‑панель

Доступна главному администратору (`MAIN_ADMIN_ID` из `.env`) и любым под‑админам, назначенным им через панель.

 Как открыть

- Выполнить `/start`  
- Появится кнопка **«⚙️ Админ панель»**  

 Возможности админ‑панели

- 👥 Список пользователей (постранично, по 10 на страницу — с кнопками «« Назад»/«Далее »»):
  - ID, имя, username  
  - персональная и кастомная ссылка  
  - премиум‑статус  

- 📊 Статистика — сводка по боту одним экраном: всего пользователей, отправлено анонимных сообщений и ответов, активных премиум, личных блокировок, пользователей в глобальном бане, создано/погашено промокодов  

- 📢 Рассылка — мастер из трёх шагов:
  1. **Аудитория**: всем пользователям или только тем, у кого активен премиум  
  2. **Звук уведомления**: со звуком или без (`disable_notification`)  
  3. **Содержимое**: текст или медиа с подписью (фото, видео, голосовое, аудио, GIF, документ, стикер — как обычное сообщение)  
  - показывает предпросмотр с числом получателей и просит подтвердить  
  - глобально забаненные исключаются из любой аудитории автоматически  
  - рассылает с ограничением скорости (запас от лимита Telegram ~30 сообщений/сек), а при `TelegramRetryAfter` ждёт и повторяет попытку один раз, прежде чем считать доставку неудачной  
  - тех, кто успел заблокировать бота, пропускает без ошибок и считает отдельно — в конце присылает итог: сколько доставлено, сколько нет  

- 👤 Под‑админы (только для главного администратора):
  - назначить пользователя админом по Telegram ID (кнопкой или сразу видит список)  
  - снять админа  
  - под‑админы получают доступ ко всей остальной панели наравне с главным администратором, кроме управления самими админами  

- ⭐ Работа с премиумом:
  - выдать премиум на:
    - +1 / +3 / +5 / +7 дней
    - или любое количество дней вручную  
  - снять премиум с пользователя  
  - таблица активных и истёкших премиум-записей — тоже постранично, по 10 на страницу  

- 🚫 Глобальный бан:
  - добавить пользователя в глобальный бан  
  - снять глобальный бан  
  - отдельный экран **«🚫 Глобальный бан-лист»** (тоже постранично) со списком всех забаненных и разбаном по кнопке  

- 🎁 Промокоды:
  - создать новый (код, дни премиума, необязательный лимит активаций)  
  - посмотреть список с количеством использований  
  - удалить код (вместе со всей историей его активаций)  

- 👁 Кто заблокировал пользователя:
  - список пользователей, которые внесли его в личный бан  
  - отдельный акцент на премиум‑пользователях  
  - разбан у конкретного пользователя по кнопке

 🗄 Структура проекта

Код разложен по пакету `bot/` вместо одного файла:

- `main.py` — тонкая точка входа: инициализация БД, сборка `Bot`/`Dispatcher`, регистрация роутеров, фоновый heartbeat для Docker healthcheck, запуск polling
- `healthcheck.py` — скрипт для `docker healthcheck`: проверяет свежесть heartbeat-файла
- `bot/core/config.py` — переменные окружения, логирование
- `bot/core/states.py` — состояния FSM (`CustomLinkStates`, `AdminPremiumStates`, `PromoStates`)
- `bot/core/runtime.py` — данные, известные только после соединения с Telegram (username бота, кэшируется при старте)
- `bot/db/` — весь доступ к данным:
  - `connection.py` — подключение к `bot_database.db` + PRAGMA (WAL, synchronous, foreign_keys)
  - `schema.py` — создание таблиц, миграция старых версий базы, индексы
  - `repository.py` — все SQL-запросы бота одним слоем, по доменам (ссылки / сообщения / блокировки / промокоды)
  - `premium.py` — премиум-система в отдельной базе `premium_users.db`, независимой от основной
- `bot/services/` — доменная логика без Telegram API: `antiflood.py` (кулдаун), `security.py` (фильтр опасных файлов), `telegram_errors.py` (разбор ошибок Bot API в понятные сообщения), `telegram_ui.py` (safe_edit_text/caption — тихо игнорируют "message is not modified"), `attachments.py` (определение типа вложения и лимитов длины), `filters.py` (not_a_command — не даёт FSM-состояниям перехватывать команды), `permissions.py` (is_admin/is_super_admin), `utils.py`
- `bot/handlers/` — роутеры aiogram: `start.py`, `messages.py`, `callbacks.py`, `admin.py`, `moderation.py`, `promo.py`, `broadcast.py`. Состояние диалога (ожидание кастомной ссылки, ввод дней премиума, создание промокода, рассылка) хранится через `FSMContext`, а не глобальные переменные
- `bot/errors.py` — глобальный обработчик ошибок
- `tests/` — набор pytest: `repository.py`, доменная логика, определение типов вложений, полный сценарий отправки/ответа через `FSMContext`, промокоды. `conftest.py` поднимает изолированную временную БД на сессию тестов

Файлы БД (`bot_database.db`, `premium_users.db`) создаются в каталоге, указанном переменной `DATA_DIR` из `.env` (по умолчанию — корень проекта; в Docker — смонтированный volume).

 🧪 Тесты

pip install -r requirements-dev.txt
pytest

`pytest.ini` настраивает `asyncio_mode = auto` (отдельный декоратор на каждый async-тест не нужен) и `pythonpath = .` — без этого голая команда `pytest` (в отличие от `python -m pytest`) не всегда добавляет корень проекта в `sys.path` и падает с `ModuleNotFoundError: No module named 'bot'` (характерно для Windows/PowerShell). Тесты используют собственную временную SQLite-базу (см. `tests/conftest.py`) — боевые `bot_database.db`/`premium_users.db` не трогают.

На каждый push и pull request в `main` тесты и проверка синтаксиса дополнительно гоняются в GitHub Actions (`.github/workflows/ci.yml`) — регресс ловится до деплоя.

 🐳 Запуск в Docker

Проект содержит `Dockerfile` и `docker-compose.yml` — это самый простой способ развернуть бота на VPS.

1. Скопируйте `.env.example` в `.env` и заполните `BOT_TOKEN` и `MAIN_ADMIN_ID`.
2. Соберите и запустите:

docker compose up -d --build

3. Логи:

docker compose logs -f

4. Остановить:

docker compose down

БД (`bot_database.db`, `premium_users.db`) хранятся в именованном Docker-volume `bot_data`, а не внутри слоя образа — пересборка образа (`--build`) их не затронет. Для просмотра/бэкапа файлов:

docker compose exec bot ls /app/data

Контейнер работает от непривилегированного пользователя и не открывает входящих портов (бот сам инициирует long polling к api.telegram.org).

У бота нет HTTP-эндпоинта, поэтому `docker ps` определяет здоровье контейнера по heartbeat-файлу: `main.py` обновляет его каждые 30 сек, а `HEALTHCHECK` в `Dockerfile` проверяет, что файл не старше 90 сек (см. `healthcheck.py`).

 📌 Идеи для доработки

- Веб‑панель для администрирования поверх текущей логики  
- Локализация самой админ‑панели — актуально теперь, когда под‑админов может быть несколько  
- Поиск пользователя в админке по ID/username вместо только постраничного просмотра  
- Переход на `aiosqlite`, если БД станет узким местом при росте нагрузки. Сейчас каждая функция `repository.py` — синхронный код без `await` внутри, поэтому даже под конкурентным диспетчером aiogram (каждый апдейт — отдельная asyncio-задача) гонок нет: событийный цикл не может прервать операцию на середине. `asyncio.to_thread` для каждого запроса сознательно не добавлен — при текущей нагрузке это дало бы только оверхед на переключение потоков без реальной выгоды в пропускной способности
